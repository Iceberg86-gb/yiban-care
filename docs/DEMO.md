# 有伴答辩操作脚本

## 演示前

- 使用 `npm run build`、`npm start` 启动本地构建版；外部字体不影响离线加载。
- 打开工作台和老人端两个窗口。投屏显示工作台，另一个窗口或手机展示老人端。
- 在演示控制台复位，确认“当前没有待处理事件”。
- 如需真实千帆调用，先在 `.env` 配置账号可用模型与 API Key，并实际生成一次摘要。不要在投屏中打开凭证文件。
- 如果无需真实 API，直接使用离线模板模式，页面会显示接入状态。

## 主线：疑似跌倒（约两分钟）

| 时间 | 操作                                 | 讲述重点                                       |
| ---- | ------------------------------------ | ---------------------------------------------- |
| 0:00 | 点击“疑似跌倒”                       | 姿态与惯性变化提供异常证据；当前数据为情境模拟 |
| 0:15 | 展开“查看感知依据”                   | 每条证据保留来源，尚未确认伤情                 |
| 0:30 | 打开老人端                           | 一次只问一个问题，按钮与文字可直接使用         |
| 0:45 | 在控制台推进 45 秒，或点击需要帮助   | 规则引擎维护时限，明确求助立即联络             |
| 1:00 | 家人点击“我来接手”                   | 送达和接手独立；模拟医疗任务仍需独立接单       |
| 1:15 | 更新“已到达现场”                     | 人工报告有来源，接手后持续跟进                 |
| 1:30 | 打开交接卡、生成摘要                 | 左侧保留事实与未知信息，右侧注明千帆或模板来源 |
| 1:45 | 填写核实结果，明确处理医疗任务并结案 | 人工确认安全、误报、责任移交有不同结果         |
| 2:00 | 查看完整时间轴                       | 沿同一条记录核查输入、规则、回执与处理过程     |

如果展示“责任移交”，必须先点击“模拟接单”取得机构回执。结案会显示接收方，不显示“确认安全”。

## 短场景：慢表达（约 30 秒）

主事件结案后启动“慢慢说，我在听”。

预设表达顺序：

- 0.5 秒：“我想……”
- 3.3 秒：“我想……找一下……”
- 6.5 秒：“我想……找一下……我女儿。”
- 9.5 秒：确认“要帮您联系周宁吗？”

点击“请联系家人”，进入求助与联络流程。本场景是时间标注的交互原型；当前没有实时 ASR、自适应端点算法或“抢话率降低”的实验结论。

## 短场景：位置异常（约 30 秒）

结案或复位后启动“位置异常”。显示虚构社区轨迹、预设围栏和采集时间；后续复用确认、联络与接手。

地图底图可以接百度地图，轨迹仍来自情境引擎。当前没有将虚构轨迹上传到鹰眼，也没有真实导航、真实 GPS 或真实机构位置。

## 故障分支

| 操作                         | 应看到什么                               |
| ---------------------------- | ---------------------------------------- |
| 老人表示“暂不需要帮助”       | 进入待人工核实，原截止时间不变           |
| 模拟当前事件收音失败         | 收音失败／回应未知，转照护者核实         |
| 启用“通知结果未知”后触发联络 | 送达待核实，点击核查模拟回执，不重复发送 |
| 家人接手后推进 60 秒         | 进展提醒并联络备用责任人                 |
| 启用“Agent 不可用”后生成摘要 | 故障注入记录、本地模板，事件规则继续运行 |
| 浏览器刷新                   | 当前事件、接手人和截止时间保留           |
| 停止并重启服务               | 恢复未完成事件，对到期任务进行处理       |
| 复位后旧请求返回             | 旧场次结果被忽略，不污染新场次           |

## 百度全栈讲述

按“芯片—框架—模型—应用”介绍任务与边界：

1. 昆仑芯、BCC／BOS：后续部署与算力适配方向，当前本机运行。
2. 飞桨／PaddleDetection：后续感知模型链路，当前预设证据。
3. 文心／千帆：已提供真实接口适配，通过当前账号实际调用后显示已验证；默认模板。
4. RTC、地图／鹰眼、小度、短信：逐项查看实际状态。浏览器播报属于终端能力，不能说已接入 RTC。

自研部分是事件规则、多端协作、受控工具、来源记录、进展跟踪和失败恢复。规划图可通过能力页的“方案原图／流程原图”打开。

## 后续八小时预算之外的优先项

1. 用实际账号验证千帆模型与工具调用、地图 AK。
2. 用真实音频验证 RTC 长停顿与续句控制，建立标注集。
3. 接入一段真实视频的飞桨推理，再做视觉／IMU 增量对照。
4. 实际路测鹰眼围栏，不用虚构轨迹声称已完成联调。
5. 如进入机构试点，再引入鉴权、数据库事务、真实通道回执和设备授权流程。
