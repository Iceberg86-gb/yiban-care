# 日常记录、分级提醒与就诊摘要

新增入口：工作台左侧「日常与趋势」，包含「日常记录」「分级提醒」「趋势与就诊摘要」。老人端正常状态显示一键记录；待处理事件优先显示确认与联络，处理完成后可继续日常记录。

## 患者简单记，家属接着补

- 用药：已按计划服用／还没服用／记不清。当前时段根据照护时区与家属计划选取，不要求填写药名、剂量或说明。
- 睡眠：睡得不错／没睡好／记不清。睡眠按醒来当天的日期记录。
- 心情：还不错／低落／不安。
- 日常变化：和平时一样／感觉不一样／想让家人看看。患者端不提供认知评分或疾病分期。
- 家属可补记近 90 天，补充观察情境、睡眠小时数、明确漏服及明显变化。普通记录静默保存，不创建联络任务。
- 家属补充附在原记录后；更新状态会保留旧记录。趋势按每一天、类别、用药时段的最新记录计算，原始重要报告和家属补充仍进入就诊摘要。

照护日期使用 `Asia/Shanghai`（页面标明北京时间），服务端保存 UTC 记录时间。患者无需选日期。当前身份与患者档案仍为比赛模拟身份，手动填写的数据标为 live，演示样本标为 simulated。

## 分级与通知

| 级别     | 输入依据                                                                   | 行为                                                                                 |
| -------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 尽快处理 | 既有疑似跌倒／位置异常事件；家属报告疑似走失、跌倒、突然明显混乱或交流困难 | 家属提醒队列优先展示；日常记录产生的严重变化立即联络，并进入现有接手、进展、结案流程 |
| 优先核实 | 家属确认漏服、已启用计划中到期未确认、非突发的明显变化、患者希望家人协助   | 创建合并的家属提醒与照护任务                                                         |
| 汇总关注 | 一般不适、近 7 天多日睡眠／情绪／行为波动                                  | 进入静默汇总，不发送即时通知                                                         |
| 常规记录 | 普通睡眠、心情、用药、行为报告                                             | 保存并更新趋势，不变成告警                                                           |

这些是照护工作优先级，不是临床风险评分。多日波动采用 3 个有记录日期的演示阈值，未经真实人群验证。

用药计划默认关闭。家属按已有医嘱填写计划名称、时段与提醒窗口后才启用。系统检查最近 24 小时内到期的窗口（支持跨午夜），未记录或记不清只提示「待核实」，不自动认定漏服。明确漏服也不产生补服、加倍或剂量建议。

同一时段／同一未闭环事件合并提醒。较轻的新记录不会解除此前高优先级提醒；结案后发生新的异常可以再次提醒。多个事件共存时优先展示高优先级事件，结束一个事件不会掩盖其他未处理事项。提醒、通知、送达、接手仍相互区分；外部通知和机构接单继续使用模拟通道。

历史补记进入报告，不按当前事故发出紧急通知。若事件正在发生，应选择今天并立即联系照护或医疗协助，不等待补记。

## 自动汇总

支持最近 7／14／30 天，随记录变化自动更新，无需等待模型或配置 API Key：

- 各类别逐日图，空缺为未记录，不以零值或正常状态替代。
- 用药报告次数、确认漏服次数及不确定记录；不将已填记录比例称为依从率。
- 主观睡眠、已知小时数的均值与样本数、情绪与行为变化日期。
- 本期和上一等长周期的记录覆盖情况，不用覆盖不同的数据宣称风险升降。
- 照护事件、责任人、处理进展、结案结果、仍需跟进的期前事项。
- 原始重要报告、家属补充、现有用药计划和尚待核实信息。
- 导出中文 Markdown 就诊摘要；结构化 JSON 可通过接口或完整场次导出获取。

14 天样本分布在今天之前的 14 天，故最近 7 天图中今天最初留空。样本有意保留部分缺失与来源标记。仅空日记允许载入，防止混入现有记录；复位将清空日记、计划与事件，界面会明确提示，先导出可保留本轮数据。

## API 与文件

- `POST /api/daily/record`：患者／家属记录，操作编号去重。
- `POST /api/daily/supplement`：家属追加说明，原记录版本校验。
- `POST /api/daily/plan`：家属用药计划，日记版本校验。
- `POST /api/daily/review`：静默提醒核实；关联事件需先在事件流程结案。
- `POST /api/daily/seed`：载入独立演示样本。
- `GET /api/daily/summary?days=7`：当前 JSON 汇总。
- `GET /api/daily/summary?days=7&format=md`：下载就诊摘要。

规则见 `server/daily.js`；共享汇总逻辑见 `shared/daily.js`；患者与家属页面见 `src/DailyCare.jsx`。数据仍在同一个本地 JSON 文件中，旧存档自动补齐新结构。

## 设计参考与验证边界

突发混乱与渐进变化分别处理。NHS 建议突然出现混乱时立即寻求医疗帮助，不能自行判断原因：[Sudden confusion](https://www.nhs.uk/symptoms/confusion/)。持续行为记录可帮助回顾情境和变化，但不能直接等同于痴呆进展：[NHS 行为变化](https://www.nhs.uk/conditions/dementia/living-with-dementia/behaviour/)。

本版本验证的是软件流程、记录完整性与提醒抑制规则；未实现临床诊断模型、真实药物风险分级、临床认证或真实医疗受理。
